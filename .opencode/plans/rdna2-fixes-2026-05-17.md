## P5: Fix MOE Semaphore Host/Device Pointer Bug

**File**: `ggml/src/ggml-cuda/moe-orchestrator.cu`  
**Lines**: 44-58

**Problem**: `hipStreamWriteValue32` at line 47 receives `&g_moe_semaphores[expert_id]` which is a host pointer. With `hipHostMallocMapped`, the host and device see different memory ranges — causes double-free/corruption in shutdown path.

**Fix**: Replace `hipHostMalloc` with `hipMalloc` for semaphore memory allocation, OR use `hipHostGetDevicePointer()` to get the device address before passing to stream functions.

**Approach A (preferred)**: Use `hipMalloc` instead of `hipHostMalloc` — semaphores don't need host access after initialization.

```cpp
// Replace line 21:
err = hipHostMalloc(&g_moe_semaphores, sizeof(uint32_t) * RDNA2_MOE_MAX_EXPERTS, hipHostMallocPortable | hipHostMallocMapped);
// With:
err = hipMalloc(&g_moe_semaphores, sizeof(uint32_t) * RDNA2_MOE_MAX_EXPERTS);
```

**Approach B**: Keep `hipHostMallocMapped` but use device pointer for stream operations:

```cpp
// In ggml_hip_moe_signal_expert_ready():
uint32_t *dev_ptr;
hipHostGetDevicePointer((void**)&dev_ptr, &g_moe_semaphores[expert_id], 0);
hipStreamWriteValue32(g_moe_stream, dev_ptr, 1, 0);
```

**Validation**: No crashes on multi-model reload, no double-free in shutdown.

## P6: Fix V8 Fallback Scratch Buffer Leak

**File**: `ggml/src/ggml-cuda/mmvq-tq.cu`  
**Lines**: 285-298

**Problem**: Static `d_act_buf` allocated on first V8 fallback call (ncols > 12288) but never freed. Leaks 48KB+ per model load.

**Fix**: Add cleanup function and call from backend shutdown.

```cpp
// Add at end of file:
void ggml_cuda_tq_cleanup() {
    static float *d_act_buf = nullptr;
    if (d_act_buf) {
        cudaFree(d_act_buf);
        d_act_buf = nullptr;
    }
}
```

**Alternative**: If ncols > 12288 is unreachable with current model set, add `GGML_ASSERT` guard:

```cpp
GGML_ASSERT(shmem_data <= 48 * 1024 && "TQ shmem exceeds 48KB limit");
```

**Validation**: No VRAM leak after 3 model reloads (check with rocm-smi).

## P2: Fix tile_y LDS Bank Conflicts

**File**: `ggml/src/ggml-cuda/mmq.cuh`  
**Lines**: 3519-3526

**Problem**: `tile_y` loaded without bank conflict padding (unlike `tile_x` which has `lds_bank_pad=2`). tile_y strides may hit 32-bank symmetry on certain quant types.

**Fix**: Add padding to tile_y allocation when stride % 32 == 0.

```cpp
// Around line 3519, compute padding:
constexpr int lds_bank_pad = 2;
int tile_y_stride = mmq_x * MMQ_TILE_Y_K;
int tile_y_pad = (tile_y_stride % 32 == 0) ? lds_bank_pad : 0;

// Use tile_y_pad when loading tile_y
```

**Gate**: `RDNA2_MATMUL_OPT_V1` (existing)  
**Validation**: Prefill t/s variance ≤±6 (current baseline)

## P3: Add rocprofv3 Counter Harness

**File**: `scripts/collect_counters.sh` (new)

**Problem**: Zero hardware counter data exists. All ISA-level claims are speculative.

**Implementation**:

```bash
#!/usr/bin/env bash
# scripts/collect_counters.sh
# Runs rocprofv3 on llama-cli and saves SQLite to benchmarks/raw/

ROCMPATH="${ROCM_PATH:-/opt/rocm}"
BINARY="${1:-build/bin/llama-cli}"
PROMPT="${2:-test prompt for inference}"

COUNTERS="SQ_INSTS_VALU,VALUBusy,MeanOccupancyPerCU,MemUnitBusy,WAVE_ISSUE_WAIT"
OUTPUT_DIR="benchmarks/raw/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$OUTPUT_DIR"

$ROCMPATH/bin/rocprof --counters "$COUNTERS" \
    "$BINARY" -p "$PROMPT" -n 128 -ngl 99 \
    --stats --stats-output "$OUTPUT_DIR/counters.h5"

echo "Results saved to $OUTPUT_DIR/"
```

**Validation**: Produces non-empty SQLite with meaningful counter values.
